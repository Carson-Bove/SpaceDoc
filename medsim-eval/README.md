# MedSim Eval (working name)

Simulation-based evaluation for crew medical digital assistants. It works with **any** assistant (SpaceDoc, CMO-DA, or a homegrown tool) and runs entirely on local hardware.

> **Research prototype.** Not for clinical use. Design and rationale: [docs/11-evaluation-system.md](../docs/11-evaluation-system.md).

**Status:** Phase A, scenario authoring. The file formats, validator, library and authoring form exist. The digital twin, runner and agents (Phases B–E) do not yet exist.

## Install

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e "medsim-eval[dev]"
```

The package doesn't depend on `spacedoc`.

## Files

Each file type is identified by its name suffix:

| Suffix | What it is | Who writes it |
|---|---|---|
| `.scenario.json` | One medical event in one mission phase | Clerks, using the authoring form |
| `.rubric.json` | That scenario's checklist and extra never events | Clerks, using the authoring form |
| `.drm.json` | A Design Reference Mission (crew, phases, EVAs, resources) | Engineering + clinical lead |
| `.habitat.json` | A vehicle or base and what medicine is possible there | Engineering, sourced research |
| `.base-rubric.json` | The generalized rubric (gates, 1–5 domains, outcomes), versioned | Clinical lead |
| `.conditions.json` | Index of the IMM conditions and their CLiFFs | Generated by a script |
| `.environments.json` | The five mission environments | Engineering |

JSON Schemas for all of them are in [`schemas/`](schemas/), generated with `medsim schema`.

## Library

The [`library/`](library/) folder holds the shared reference data:

- **`drms/`**: DRMs taken from NASA Integrated Medical Model service-request reports. Each file cites its report.
- **`habitats/`**: vehicle and base profiles. Every item carries a source or an `assumption` flag.
- **`conditions/`**: the CLiFF index. Rebuild it with `python medsim-eval/scripts/build_cliff_index.py`, which always picks the most recent CLiFF version.
- **`rubrics/`**: base rubrics. A new version is a new file (`general-0.2.base-rubric.json`), and each scenario rubric pins the version it was written against, so updating the rubric never silently changes old scores.

## Validate

```bash
medsim validate scenarios/            # everything in a folder
medsim validate path/to/X.scenario.json
medsim validate --strict scenarios/   # warnings fail too
```

The validator checks three things:

- **Schema:** every file matches its format.
- **Cross-references:** the DRM, phase, crewmember, condition and base-rubric version exist; the mission day falls inside the phase.
- **Reviewer warnings:** vague words in yes/no rubric items, unknown state variables, deadlines after the scenario ends, and drugs or equipment that aren't aboard.
