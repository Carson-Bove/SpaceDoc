# MedSim Eval (working name)

Simulation-based evaluation for crew medical digital assistants. It works with **any** assistant (SpaceDoc, CMO-DA, or a homegrown tool) and runs entirely on local hardware.

> **Research prototype.** Not for clinical use. Design and rationale: [docs/11-evaluation-system.md](../docs/11-evaluation-system.md).

**Status:** Phase A (scenario authoring) is built: file formats v0.2, validator, library and the offline Scenario Builder. The digital twin, runner and agents (Phases B–E) are not built yet.

## Install

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e "medsim-eval[dev]"
```

The package doesn't depend on `spacedoc`.

## Files

Each file type is identified by its name suffix:

| Suffix | What it is | Who writes it |
|---|---|---|
| `.scenario.json` | A medical case: patient, condition, where it can happen, speaker, course of illness, correct answer | Clerks, using the Scenario Builder |
| `.rubric.json` | That scenario's checklist items and extra never events | Clerks, using the Scenario Builder |
| `.crew.json` | The roster: 20 fictional crewmembers with charts, training and baselines | Engineering + physiologist |
| `.drm.json` | A Design Reference Mission (crew, phases, EVAs, resources) | Engineering + clinical lead |
| `.habitat.json` | A vehicle or base and what medicine is possible there | Generated from NASA kit tables |
| `.environments.json` | The five mission environments and the DRM phase each runs in | Engineering |
| `.conditions.json` | The 118 IMM conditions: CLiFF links, course, where they happen | Generated by a script |
| `.physiology.json` | Normal ranges and in-flight changes | Physiologist |
| `.symptoms.json` | ICD-10-CM symptom codes | Generated by a script |
| `.encyclopedia.json` | Kit drugs (FDA label excerpts) and space terms | Generated by a script |
| `.base-rubric.json` | The generalized rubric (gates, 1–5 domains, standard items, item library), versioned | Clinical lead |

JSON Schemas for all of them are in [`schemas/`](schemas/), generated with `medsim schema`.

## Library

The [`library/`](library/) folder holds the shared reference data:

- **`drms/`**: DRMs taken from NASA Integrated Medical Model service-request reports. Each file cites its report. Clerks don't pick them; each environment's representative DRM phase is set in `environments/`.
- **`crew/`**: the fictional crew roster, modelled on NASA's active corps.
- **`habitats/`**: vehicle and base profiles. Every item carries a source or an `assumption` flag.
- **`conditions/`**: the CLiFF index. Rebuild it with `python medsim-eval/scripts/build_cliff_index.py`, which always picks the most recent CLiFF version.
- **`rubrics/`**: base rubrics. A new version is a new file (`general-0.2.base-rubric.json`), and each scenario rubric pins the version it was written against, so updating the rubric never silently changes old scores.

## Scenario Builder (the authoring form)

[`dist/scenario-builder.html`](dist/scenario-builder.html) is one self-contained HTML file. Clerks download it and double-click it; it needs no internet. The DRMs, conditions, habitats and base rubric are built into the file. See the [guide for clerks](../docs/scenario-builder-guide.md).

Rebuild it after any library change (a test fails if the committed copy is stale):

```bash
medsim build-form
```

The source is [`form/template.html`](form/template.html).

## Updating the library from NASA

```bash
python medsim-eval/scripts/extract_imm_kits.py    # kit tables -> library/sources/imm-medkits.json
python medsim-eval/scripts/build_habitats.py      # kit tables + specs -> library/habitats/
python medsim-eval/scripts/build_cliff_index.py   # NASA page + 2023 CLiFFs -> library/conditions/
python medsim-eval/scripts/build_symptoms.py      # ICD-10-CM -> library/symptoms/
python medsim-eval/scripts/build_encyclopedia.py  # DailyMed labels + glossary -> library/encyclopedia/
medsim build-form && medsim schema && pytest medsim-eval
```

These need `pdftotext` (poppler-utils) and network access. Habitat files are generated: edit `PROFILES` in `build_habitats.py`, not the JSON. DRM files are maintained by hand.

## Validate

```bash
medsim validate scenarios/            # everything in a folder
medsim validate path/to/X.scenario.json
medsim validate --strict scenarios/   # warnings fail too
medsim migrate scenarios/inbox/       # convert v0.1 scenarios, keeping .v0.1.bak copies
```

No GitHub Actions run these; run them locally before merging scenarios.

The validator checks three things:

- **Schema:** every file matches its format.
- **Cross-references and clinical sense:** the crewmembers, condition, symptom codes and base-rubric version exist; the condition fits the patient (sex, and no appendicitis after an appendectomy); NKDA isn't contradicted by a drug allergy.
- **Reviewer warnings:** environments the CLiFF doesn't expect, vague words in yes/no rubric items, unknown state variables, deadlines after the run ends, a time-critical treatment that isn't aboard somewhere, and a missing etiology. Notes (not warnings) say where a rubric item doesn't apply because its equipment isn't aboard.
